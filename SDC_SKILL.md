# ShuttleBuilder UI map

Generated by `manage.py sdc_teach` on 2026-11-02. Crawled as: anonymous, user teacher. All paths are relative to the site root.

## How to operate this app

- The app is a single page. Views are SDC controllers nested by the `sdc-navigator`; the URL path lists them separated by `~`: `/~parent-view~child-view`.
- Arguments follow after `~&` as `key=value` pairs joined by `&`: `/~main-view~&id=5`. A key may be prefixed with the view depth (`1.id`, `2.id`) to target one view of the path; arguments are handed to the view as `data-*` attributes / `this.params`.
- Relative paths: `..` goes one view up, `*` keeps the current view at that depth, `.` is the current path (e.g. `..~other-view`).
- Navigate in the browser with `window.sdcNav.goTo("/~view-a~view-b", {key: value})` or open the URL directly; links with class `navigation-links` do the same.
- Buttons call controller methods named in their `sdc_click` attribute (`sdc_click="method"`); `events.click[".selector"]` marks handlers registered in the controller `events` list.
- A view is ready when `window.sdcNav && !window.sdcNav._is_processing` and no `.sdc_sub_detail_container.loading` element exists.
- Server calls (`this.serverCall(...)`) execute methods of the matching `SDCView` on the server; model-socket calls load/save model data.
- Buttons marked "skipped" were not executed by the crawler because they look destructive (delete/logout/save/submit); their effect is unknown — confirm with the user before clicking them.
- Forms were not submitted automatically; "submitted by developer" shows what a manual submit did, "not submitted" means the outcome is unknown.
- A view showing `sdc-error 403` needs a logged-in user with the right permissions.
- All SdcModel WebSocket traffic (`/sdc_ws/model/<Model>`) was recorded per controller: "Model socket (on load)" lists what each controller requests when the view opens, buttons and forms list what they trigger, as `Model.event(args)` with the `model_query` filter keys. `connect` subscribes to live updates of the filtered rows; `load`, `save`, `create`, `delete`, ... read or write data.

## Controllers

### `<basic-info>`

Start page of the ShuttleBuilder: explains what a Shuttle is and how to install one.

- Static help text; no data is shown or changed. No login required.
- Describes the workflow: create a Shuttle in `<shuttle-instance-list>`, download the executable, install it on the lab PC.
- Contains install steps for Windows, Windows XP with SFTP and Linux (systemd), with links to the needed helper files.
- Links to `<shuttle-scripts>` for preprocess scripts, the OpenAPI file and the Chemotion documentation.

_app `main_app`, server view `main_app.sdc_views.BasicInfo`, Django URL `/sdc_view/main_app/basic_info`_

### `<git-insatnce-edit>`

Form to link a new git repository or edit an existing `GitInstance`.

- Arguments: `pk` (optional) is the id of the repo to edit; without it a new repo is created.
- New repo: "Save & Done" creates it and returns to `<git-instance-list>`. It is not active until activated there.
- Edit: there is no save button; changes are stored by the model form directly.
- The `name` cannot be changed after creation. Changing `url` or `branch` takes effect on the next reload/activation.
- Requires login.

_app `main_app`, server view `main_app.sdc_views.GitInsatnceEdit`, Django URL `/sdc_view/main_app/git_insatnce_edit`_

### `<git-instance-list>`

List of all linked git repositories (`GitInstance`) with Shuttle source code; the active one is marked `ACTIVE`.

- "Activate" (inactive repos) clones the repo and makes it the only active one; Shuttles are then built from it.
- "Reload" (active repo) clones it again to pick up new commits.
- Both run on the server and can take a while; a loading screen is shown. All Shuttles are rebuilt on their next download.
- "NEW" opens `<git-insatnce-edit>` to link a repo; the wrench edits one; the trash button deletes it after a confirm dialog.
- Requires login.

_app `main_app`, server view `main_app.sdc_views.GitInstanceList`, Django URL `/sdc_view/main_app/git_instance_list`_

### `<register>`

Registration form that creates a new `SdcUser` account; open it from the "Register" link of `<sdc-login>` or `<sdc-user-nav-btn>`.

- Arguments: `model` must be `SdcUser`; `next` is where to go after creating (the links pass `..`, i.e. back).
- Fields: `username`, `first_name`, `last_name`, `email`, the password and its confirmation (must match and pass the password rules).
- "Create" creates the account; anyone may register, no login is needed. The new user is not logged in automatically.
- If an `email` was given, a confirmation e-mail with a link to `<sdc-confirm-email>` (valid 3 days) is sent to it.
- If the project requires confirmed e-mail addresses, the new user can only log in after following that link.

_app `sdc_user`, server view `sdc_user.sdc_views.Register`, Django URL `/sdc_view/sdc_user/register`_

### `<sdc-login>`

Login form (username and password) that starts a session for an `SdcUser`; the view other views redirect to when login is required.

- Arguments: `next` (optional) is the URL to go to after login; without it the project's start page (`LOGIN_SUCCESS`) is used.
- "Login" checks the credentials. On success the user is logged in and the whole page reloads at the `next` target; on failure the errors are shown in the form.
- If the project requires confirmed e-mail addresses and the user has not confirmed theirs, login is refused and a new confirmation e-mail is sent.
- Links lead to `<sdc-password-forgotten>` and to `<register>`.

_app `sdc_user`, server view `sdc_user.sdc_views.SdcLogin`, Django URL `/sdc_view/sdc_user/sdc_login`_

### `<sdc-model-form>`

Generic create/edit form for one record of an SDC model, generated from the model's server-side form; saves via the model socket.

- Arguments: `model` (required) is the SDC model name; with `pk` (or `id`) it edits that record, without it it creates a new one (e.g. `/~sdc-model-form~&model=Author&pk=3`).
- Edit mode: every field change is saved automatically, there is no save step; with `form_name=<name>` a named alternative form of the model is used, and with `auto_save=false` changes are only stored when the save button (`button_text`, default "Save") is pressed.
- Create mode: "Create" creates the record and then navigates to `next` (default `..`, one level up); `reset_on_save=true` instead clears the form for another entry, `editing_after_save=true` switches to editing the new record.
- After a successful save of an existing record the form navigates to `next` if given.
- Other optional arguments: `form_header` (heading text) and `filter` (selects the record to edit instead of `pk`).
- Validation errors are shown at the fields; who may create or edit is decided by the model's server-side permissions.
- Also used as a mixin by app-specific form controllers.

_app `sdc_tools`, server view `sdc_tools.sdc_views.SdcModelForm`, Django URL `/sdc_view/sdc_tools/sdc_model_form`_

## Data models

SDC models are loaded and saved over the model WebSocket (`this.querySet("Name", {filter})` in a controller).

### `ElnConnection` (main_app)

Connection to a Chemotion ELN server whose accounts may log in to the ShuttleBuilder.

- `url`: base URL of the Chemotion instance; `active`: only the active connection is used for login.
- `token`, `device`: optional Chemotion API token and device id for this connection.
- If no connection is active and the setting `ELN_URL` exists, an active connection to it is created automatically.
- Users who log in with Chemotion credentials get a local account; new ones become staff if they are Chemotion admins.
- Managed in the Django admin (`/admin/main_app/elnconnection/`); saving one as active deactivates all others.
- `<shuttle-login>` shows the active connection's URL.

Fields: `id` (BigAutoField), `url` (CharField), `active` (BooleanField), `token` (CharField), `device` (IntegerField)

### `ElnUser` (main_app)

Per-user profile that records whether a user logs in through the connected Chemotion ELN.

- One record per Django `User` (`user`, one-to-one); created automatically when a user is created.
- `is_eln_user`: `true` if the last login was verified by the active `ElnConnection`, `false` for a local account login.
- `token`: Chemotion API token from the last ELN login; empty for local logins.
- Both fields are set by the login process, not by the user.
- Each user can only read their own record; deleting the `User` deletes it.

Fields: `id` (BigAutoField), `user` → `SdcUser`, `token` (CharField), `is_eln_user` (BooleanField)

### `GitInstance` (main_app)

A git repository (and branch or commit) holding the Shuttle source code that executables are built from.

- `name`: unique, cannot be changed later; `url`: clone URL; `branch`: branch name or commit id (default `main`).
- `is_active`: exactly one repo is active; all Shuttle builds use it.
- `last_reload`: when the repo was last cloned; `null` means it is cloned on the next build.
- If none is active, the default `ComPlat/shuttle/Main` (https://github.com/ComPlat/shuttle.git, `main`) is created and activated.
- Activating or reloading a repo clones it again; afterwards every `ShuttleInstance` is rebuilt on its next download.
- Readable and editable by every logged-in user.
- Listed and activated in `<git-instance-list>`, created/edited in `<git-insatnce-edit>`.

Fields: `id` (BigAutoField), `name` (CharField), `url` (CharField), `branch` (CharField), `is_active` (BooleanField), `last_reload` (DateTimeField)

### `ShuttleInstance` (main_app)

Configuration of one Shuttle: a small program for a lab PC that watches a folder and uploads new data.

- `name`: unique, cannot be changed later; `src`: folder to watch on the lab PC; `duration`: seconds a file must stay unchanged before it is sent (default 300).
- `transfer`: `webdav` or `sftp`; `dst`, `user`, `password`: target URL and credentials on the server.
- `shuttle_type`: `file` (each file), `folder`, `zip`, `tar` (whole folder once complete) or `flat_tar` (files grouped by the `common_name_parts` regex).
- `architecture`: target system: `win_i386`, `win_64`, `ubuntu_64`, `raspberry_pi_6`, `raspberry_pi_7` or `raspberry_pi_64`.
- `with_converter`: also convert data to a BagIt archive, sent to `dst_bagit` with `user_bagit`/`passwort_bagit`; needs a JSON `profile`, `public_link` is the URL prefix of the raw files.
- `owner`: the creating user. Logged-in users see and change only their own instances; staff and superusers see all.
- Downloading compiles the executable from the active `GitInstance` (slow on first download or after changes); deleting also removes the build files.
- Listed in `<shuttle-instance-list>`, created/edited/copied in `<shuttle-instance-edit>`.

Fields: `id` (BigAutoField), `name` (CharField), `user` (CharField), `password` (CharField), `transfer` (CharField), `src` (CharField), `dst` (CharField), `shuttle_type` (CharField), `common_name_parts` (CharField), `duration` (PositiveIntegerField), `architecture` (CharField), `with_converter` (BooleanField), `user_bagit` (CharField), `passwort_bagit` (CharField), `dst_bagit` (CharField), `public_link` (CharField), `profile` (FileField), `last_update` (DateTimeField), `last_build` (DateTimeField), `owner` → `SdcUser`

### `SdcUser` (sdc_user)

A user account of the site (the project's Django user model); one record per person who can log in.

- `username` (unique, used to log in), `first_name`, `last_name`, `email`; `is_staff`, `is_superuser`,
  `is_active`, `groups`, `date_joined`, `last_login` as in Django's standard user.
- `email_confirmed`: `true` once the user followed the link in the confirmation e-mail (`<sdc-confirm-email>`).
- The password is never sent to the client; it is changed with the `password_form` (`<sdc-change-password>`)
  or reset by e-mail (`<sdc-password-forgotten>`).
- Anyone may create an account (registration in `<register>`). By default a logged-in user can read and
  edit only their own record (`username`, names, `email`); superusers can see and edit all users, and only
  superusers may delete users.
- Saving a new or changed `email` resets `email_confirmed` to `false` and sends a confirmation e-mail to
  that address (link valid for 3 days).
- Edited in `<sdc-model-form>` via the "Edit <username>" link of `<sdc-user-nav-btn>`; `<sdc-user>` loads
  the current user's record.

Fields: `id` (BigAutoField), `last_login` (DateTimeField), `is_superuser` (BooleanField), `username` (CharField), `first_name` (CharField), `last_name` (CharField), `email` (CharField), `is_staff` (BooleanField), `is_active` (BooleanField), `date_joined` (DateTimeField), `email_confirmed` (BooleanField), `groups` → `Group`, `user_permissions` → `Permission`
